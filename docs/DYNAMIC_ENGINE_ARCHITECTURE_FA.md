# معماری پایه موتور پویای پنگ

## هدف

هدف، تبدیل تدریجی برنامه از مجموعه فرم‌های ثابت به سکویی است که سؤال‌ها، عکس‌ها، قواعد و گزارش‌ها را از فراداده نسخه‌دار تولید کند. نسخه پایدار خودرو و ماژول آزمایشی آتش‌سوزی تا زمان آماده‌شدن جایگزین‌ها حفظ می‌شوند.

## اجزای پنگ ۲.۰

- کاتالوگ‌های نسخه‌دار دامنه
- قراردادهای داده مبتنی بر طرح‌واره
- طبقه‌بندی شواهد
- وضعیت‌های کنترل‌شده تصمیم پوشش
- بارگذار امن فایل‌های دامنه
- موتور ارزیابی شرایط پوشش
- بسته‌های پویا برای چند خسارت خاص اموال
- آزمون‌های ماشینی صحت ساختار و ممنوعیت تصمیم خودکار

## مرز اعتماد

فایل‌های دامنه، تنظیمات اجرایی هستند و باید مانند کد کنترل نسخه شوند. مسیرهای موجود در فهرست دامنه کنترل می‌شوند و امکان پیمایش به مسیرهای خارج از دامنه ندارند. قواعد نباید با اجرای مستقیم متن برنامه‌نویسی پیاده شوند.

استفاده از موارد زیر در قواعد ممنوع است:

```text
eval
new Function
arbitrary JavaScript expressions
```

## نسخه‌گذاری پرونده

هر پرونده پویا در مراحل بعد باید شناسه و نسخه بسته‌های استفاده‌شده را کنار داده‌های خود نگه دارد. انتشار نسخه جدید نباید پرونده قدیمی را به‌طور خاموش تغییر دهد.

## بسته‌بندی Android

پوشه اصلی دامنه در ریشه پروژه نگهداری می‌شود. وظیفه ساخت Android آن را هنگام ساخت به دارایی‌های PWA منتقل می‌کند. بنابراین کاتالوگ‌های منبع یک نسخه بیشتر ندارند و داخل APK به‌صورت آفلاین در دسترس قرار می‌گیرند.

## موارد هنوز پیاده‌سازی‌نشده

- مهاجرت کامل فرم خودرو به نمایشگر پویای طرح‌واره
- فرم‌ساز مدیریتی
- انتشار امضاشده کاتالوگ‌ها از سرور
- موتور نرخ رسمی و حق‌بیمه
- گزارش‌ساز کامل چندمحصولی
- گردش تأیید چندسطحی سازمانی
- اتصال به سامانه مرکزی

این موارد باید مرحله‌ای و پس از آزمون سازگاری خودرو اضافه شوند.
